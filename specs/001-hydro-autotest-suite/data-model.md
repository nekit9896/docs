# Data Model: Автоматизированные тесты гидрорасчёта (Гидроуклон)

**Date**: 2026-11-18 | **Spec**: [spec.md](./spec.md)

Сущности извлечены из Key Entities spec и требований FR-001…FR-013. Описывают данные проверок и прогонов, не реализацию.

## Сущности

### Case (кейс каталога)

- `case_id`: строка, уникальна и неизменяема — `HY-CALC-NNN` / `HY-HIST-NNN` / `HY-SYS-NNN` (FR-007)
- `suite`: enum {`hy_calc`, `hy_hist`, `hy_sys`}
- `title`: краткое описание ожидаемого поведения
- `rules`: правила исполнения из тест-планов: входные данные, точки контроля, окна ожидания
- `reference`: эталон кейса (CaseReference)
- `markers`: признаки для выборочного запуска (набор, длительность, требования к состоянию стенда)
- Связь: 1 Case → 1 тестовый модуль (соглашение R3); 1 Case → N CaseResult (история прогонов)

### CaseReference (эталон кейса) — FR-011

- `version`: целое, растёт при каждом утверждённом изменении
- `expected`: ожидаемые значения/поведения по точкам контроля
- `tolerance`: точность сопоставления (из правил исполнения кейса)
- `change_log`: запись об изменении — что изменилось, почему, кто утвердил, дата

### Run (прогон) — FR-008

- `run_id`: строка (дата-время или uuid)
- `started_at` / `finished_at`: метки времени
- `env`: снимок EnvironmentConfig на момент запуска
- `catalog_snapshot`: версия каталога кейсов на момент запуска (edge case: изменение каталога во время прогона)
- `status`: enum {`created`, `running`, `completed`, `aborted`}
- Связь: 1 Run → N CaseResult

### CaseResult (результат проверки кейса) — FR-004

- `run_id` → Run; `case_id` → Case
- `verdict`: enum {`passed`, `failed`, `skipped`, `infra_error`} — `infra_error` означает не выполненный по инфраструктурной причине прогон, а не провал поведения
- `mismatches`: список расхождений {точка контроля, ожидалось, фактически, точность} — обязателен для `failed` (SC-005)
- `duration_s`: длительность проверки
- `skip_reason`: причина пропуска — обязательна для `skipped`
- `infra_reason`: инфраструктурная причина — обязательна для `infra_error`

### CoverageEntry (карта покрытия) — FR-012

- `case_id` → Case
- `automated`: булев признак
- `test_ref`: ссылка на тестовый модуль (когда `automated = true`)
- `reason`: причина непокрытия (когда `automated = false`)

### EnvironmentConfig (окружение стенда) — R7

- `name`: имя окружения (тестовый стенд)
- `endpoints`: адреса и порты сервисов и баз данных (уточняются — R9)
- `messaging`: каналы обмена данными (уточняются — R9)
- `credentials_ref`: ссылки на секреты (не сами значения)
- `reserved_tags`: закреплённые тестовые теги (MT1.LU1, MT1.LU2)

## Правила валидации

- `case_id` уникален и неизменяем; каждый CaseResult ссылается на существующие Run и Case (FR-007)
- `verdict` строго из enum; для `failed` обязателен `mismatches`, для `skipped` — `skip_reason`, для `infra_error` — `infra_reason` (SC-005)
- обновление эталона увеличивает `version` и пишет запись в `change_log` (FR-011)
- Run не стартует без снимка каталога и env-конфига
- прерванный прогон (`aborted`) позволяет повторить только незавершённые кейсы (edge case spec)

## Переходы состояний

```text
Run.status:      created → running → completed
                            └──────→ aborted   (прерван посреди выполнения)

CaseResult.verdict: выставляется один раз по итогам проверки;
                    повторная проверка создаёт новую запись CaseResult
```
