# Quickstart: валидация автотестов гидрорасчёта

**Date**: 2026-11-18 | **Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

Валидационный сценарий «с нуля до отчёта»: подтверждает FR-001…FR-008 на MVP (User Story 1, набор HY-CALC). Это руководство по запуску и проверке, не реализация.

## Предусловия

- Развёрнут тестовый стенд Гидроуклона (задачи 0.1–0.2 роадмапа): сервисы расчёта, истории и моделирования, шлюз; базы model/points/calc (PostgreSQL) и history/alarms/model (ClickHouse), Redis, каналы обмена.
- Выданы доступы: учётная запись `-a`, доступ scada_docker (SSH в два прыжка), учётки Kafka/Redis/PostgreSQL/ClickHouse, TestOps (задача 0.1).
- Python 3.12+, доступ к библиотеке lds-autotest (задача 0.26).
- Закреплены тестовые теги MT1.LU1 и MT1.LU2 (задача 0.19).

## Шаги

1. **Окружение**: `python -m venv .venv && pip install -e .` — зависимости из `pyproject.toml`, включая lds-autotest.
2. **Конфиг**: скопировать `config/env/example.yaml` в `config/env/test-stand.yaml`, заполнить адреса и каналы обмена (задача 0.25); секреты передать через переменные окружения.
3. **Восстановление начального состояния**: `pytest -m stand_depends --setup-only` — фикстуры очистки (задачи 0.11/0.12).
4. **Smoke**: `pytest -m smoke` — ожидание: код выхода 0 (стенд готов) либо 3 (инфраструктурная проблема, см. [contracts/run-cli.md](./contracts/run-cli.md)).
5. **Прогон MVP**: `pytest -m hy_calc --junitxml=reports/junit.xml --report-json=reports/run.json`.
6. **Проверка отчёта**: в `reports/run.json` каждый результат содержит `case_id` и вердикт из enum, провалы — с `mismatches` (контракт [contracts/report-schema.md](./contracts/report-schema.md)).

## Ожидаемые результаты

- Каждый кейс набора получает вердикт `passed`/`failed`/`skipped`/`infra_error` (FR-004).
- Сводный отчёт содержит все задействованные кейсы, причины провалов и непроверенные точки контроля (FR-008, SC-005).
- Код выхода соответствует таблице [contracts/run-cli.md](./contracts/run-cli.md).
- Повторный запуск тех же кейсов на восстановленном стенде даёт те же вердикты (FR-005, SC-003).
- Недоступность стенда даёт `infra_error`, а не `failed` (edge cases spec).
