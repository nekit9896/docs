# HY-HIST-041 — Доступ к несуществующей сессии (404)

**Требование:** R-HYDR-075
**Описание:** Запрос к несуществующему sessionId возвращает HTTP 404. Система не
должна падать с 500 или возвращать пустой объект. 404 — корректная реакция:
«такой сессии нет».

**Предусловие:**

- Сессия с ID `0000` **не существует**
- Стенд в начальном состоянии (нет сессий)

**Действия:**

1. `api.get("0000")` ⚠️ — 404. Тело: `{"error":"Session not found"}` или аналогичное
2. `api.start("0000")` ⚠️ — 404 (не 409, не 500): «не нашла» (404) vs «нашла, но
   нельзя» (409) — здесь «не нашла»
3. `api.pause("0000")` ⚠️ — 404
4. `api.close("0000")` ⚠️ — 404
5. `api.watermark("0000")` ⚠️ — 404
6. `pg.query("SELECT * FROM sessions WHERE id = '0000'")` — 0 строк: сессии
   действительно нет в БД

**Ожидаемый результат:**

| Шаг | Операция | Ожидаемый код | Пояснение |
|---|---|---|---|
| 1 | GET | 404 | Сессия не найдена |
| 2 | START | 404 | Нельзя запустить то, чего нет |
| 3 | PAUSE | 404 | Нельзя приостановить то, чего нет |
| 4 | CLOSE | 404 | Нельзя закрыть то, чего нет |
| 5 | WATERMARK | 404 | Нельзя прочитать то, чего нет |
| 6 | PG query | 0 строк | Подтверждение: сессии нет в БД |

**Примечание:** Если для `api.close` возвращают 204 (No Content) вместо 404 —
допустимо (идемпотентность). Но для GET/START/PAUSE — строго 404.

**Teardown:** `RESET()`
