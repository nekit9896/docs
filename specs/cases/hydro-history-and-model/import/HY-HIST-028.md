# HY-HIST-028 — Импорт: невалидный формат

**Требование:** R-HYDR-066
**Описание:** Оператор загружает файл с битым содержимым (не XLSX, не ZIP —
просто текстовый мусор). Система отклоняет с ошибкой, не испортив сессию. После
отклонения возможен повторный импорт с корректным файлом.

**Причинно-следственная связь:** Если система зависла на битом файле (исключение,
сбой парсера) — сессия может остаться в неопределённом состоянии (IMPORTING = 6
навечно). Важно проверить: (а) ошибка возвращается как 400; (б) сессия остаётся в
предыдущем статусе (CREATED = 0); (в) повторный импорт возможен.

**Предусловие:** Сессия modelling создана (status = 0).

**Действия:**

1. `api.import_(id, file=binary_garbage.bin)` ⚠️ — случайные байты (или текст
   «hello world»). Система: определяет, что формат не распознаётся, возвращает
   400, НЕ меняет статус сессии
2. `WAIT(3)` — ошибка должна быть синхронной
3. `api.get(id)` ⚠️ — сессия **не повреждена**: status = 0 (CREATED), нет полей с
   ошибкой импорта, `importStatus` отсутствует или = 0
4. `api.import_(id, file=valid.xlsx)` ⚠️ — повторный импорт с корректным файлом
5. `WAIT(5)`
6. `api.get(id)` ⚠️ — status = 7 (IMPORTED); импорт после ошибки — успешен

**Ожидаемый результат:**

| Шаг | Ожидание | Пояснение |
|---|---|---|
| 1 | HTTP 400, `{"error":"Invalid file format"}` | Формат не распознан |
| 3 | `status = 0` (CREATED) | Сессия не повреждена |
| 6 | `status = 7` (IMPORTED) | Повторный импорт успешен |

**Teardown:** `api.close(id)` ⚠️ → `RESET()`
