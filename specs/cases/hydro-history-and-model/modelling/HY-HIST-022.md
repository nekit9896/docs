# HY-HIST-022 — modelling: advance на большой интервал (1 час)

**Требование:** R-HYDR-065
**Описание:** Оператор продвигает виртуальное время на 1 час (3600 с) одним
вызовом `advance`. Система должна: корректно увеличить watermark на 3600 с;
если в буфере (из импорта) есть данные за интервал — опубликовать их в Kafka;
если данных нет — просто продвинуть watermark без публикации.

**Причинно-следственная связь:** В modelling оператор полностью контролирует
время. Один `advance(3600)` = «прошёл 1 час виртуального времени». Если файл
импорта не загружался и значения не задавались — hydro-calculation получит
«пустое» время и рассчитает по последним известным значениям.

**Предусловие:**

- Сессия modelling создана и запущена (status = 3, PLAYING)
- `watermark` = начальное значение (`2026-11-09T09:00:00Z`)
- Файл импорта **не** загружен (сценарий без данных)
- Конфигурация ТУ1 загружена

**Действия:**

1. `api.watermark(id)` ⚠️ — зафиксировать текущий watermark. Ожидаем:
   `2026-11-09T09:00:00Z`
2. `api.advance(id, 3600)` ⚠️ — сдвиг на 1 час вперёд. Система: (а) увеличивает
   watermark на 3600 с; (б) если в буфере есть данные за 09:00–10:00 —
   публикует их в `model_main_{id}`; (в) если нет — просто продвигает watermark.
3. `WAIT(5)` — время на публикацию в Kafka, расчёт, обновление watermark в Redis.
4. `api.watermark(id)` ⚠️ — ожидаем `2026-11-09T10:00:00Z` (09:00 + 1 час),
   разница с шагом 1 — ровно 3600 с (± 2 с).
5. `api.get(id)` ⚠️ — `messagesProcessed` и `messagesDropped`: без импорта
   `messagesProcessed` не должен резко вырасти.
6. `hmi.get("MT1.LU1.SGLU1.KIP1.TI.Head")` ⚠️ — hydro-calculation пересчитал:
   значение существует (≠ null), рассчитано по последним входам.

**Ожидаемый результат:**

| Шаг | Ожидание | Пояснение |
|---|---|---|
| 1 | `watermark = "2026-11-09T09:00:00Z"` | Исходное состояние |
| 4 | `watermark = "2026-11-09T10:00:00Z"` | +3600 с |
| 5 | `messagesProcessed` не изменилось (без импорта) | Нет данных для публикации |
| 6 | `Head` имеет значение (≠ null) | Hydro-calc рассчитал по последним входам |

**Примечание:** Если advance на 1 час вызывает внутренний «разброс» на подшаги
(например, по 60 с) — допустимо. Главное: итоговый watermark = 09:00 + 3600 с.

**Teardown:** `api.stop(id)` ⚠️ → `api.close(id)` ⚠️ → `RESET()`
