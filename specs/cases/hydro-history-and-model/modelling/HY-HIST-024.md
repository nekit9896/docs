# HY-HIST-024 — modelling: отрицательный advance (откат времени)

**Требование:** R-HYDR-065
**Описание:** Оператор пытается откатить время назад: `advance(-60)`. Watermark —
монотонная величина, не может двигаться назад. Ожидаемое поведение: система
отклоняет запрос с ошибкой 400.

**Причинно-следственная связь:** Watermark — «фронт» обработки. Откат назад →
hydro-calculation получит данные «из прошлого» повторно → дубли в расчётах,
нарушение логики алармов. Откат должен быть запрещён на уровне валидации.
Альтернативное поведение (не предпочтительное): допуск отката ломает модель —
уже обработанные сообщения не «возвратятся» из Kafka, алармы уже сработали.
Поэтому **ожидаем отказ**.

**Предусловие:** Сессия modelling запущена, `watermark = "2026-11-09T09:05:00Z"`.

**Действия:**

1. `api.advance(id, -60)` ⚠️ — откат на 1 минуту; ожидаем отказ (валидация:
   seconds < 0 недопустим)
2. `WAIT(2)` — обработка запроса (400 приходит синхронно)
3. `api.watermark(id)` ⚠️ — watermark **не изменился**: `09:05:00`
4. `api.get(id)` ⚠️ — статус сессии не изменился (PLAYING = 3), ошибок нет

**Ожидаемый результат:**

| Шаг | Ожидание | Пояснение |
|---|---|---|
| 1 | HTTP 400, `{"error":"advance seconds must be positive"}` | Отрицательное значение отклонено |
| 3 | `watermark = "2026-11-09T09:05:00Z"` | Не изменился |
| 4 | `status = 3` (PLAYING) | Сессия не пострадала |

**Примечание:** _(Допущение 10: отрицательный advance отклоняется с 400. Если
реализация допускает откат — требует отдельного обсуждения с разработкой.)_

**Teardown:** `api.stop(id)` ⚠️ → `api.close(id)` ⚠️ → `RESET()`
